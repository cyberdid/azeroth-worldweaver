# Agent helper tools

These scripts provide both game-chat adapters, read-only access to shared AzerothCore telemetry and static world data, plus a verified WoW-window capture helper. Start with the repository [configuration guide](../../README.md#configuration) and [security notes](../../SECURITY.md).

The direct `world_query.py` helper reads the server configuration path from `WOW_SERVER_CONFIG` or `--config`. The bridge relay serves only the named operations in `world_query_service.py`; requests contain typed arguments and never SQL or connection secrets. The chat adapters can also submit one fixed, server-validated playerbot action when an authorized user directly addresses that bot. The server's separate `ClaudeBridge.AuthorizedPlayers` setting must name the same allowed characters; leaving it empty denies actions.

`world_state.py` validates snapshot and event sequence data. `wow_window_capture.py` only captures the active, mapped WoW window whose process can be verified, and the adapters invoke it only for explicit visual requests. A private inter-process lock serializes simultaneous requests so both agents reuse the same recent frame; ordinary prompts do not attach an old image. World telemetry continues independently. Both adapters require an explicit sender allowlist. The Claude adapter runs with read-only file tools and a single typed world-query command pattern; its game directives are limited to a fixed playerbot allowlist.

The first action allowlist is `follow`, `stay`, `attack_master_target`, `attack_nearby`, `loot_nearby`, `fish_here`, `use_fishing_bobber`, and `stop_fishing`. A correlated server acknowledgement means the playerbot accepted the primitive; the adapters must inspect later telemetry before claiming it completed. See the root README for current implementation status. The dispatcher builds and is deployed on the author's live server; in-game execution remains to be verified.
