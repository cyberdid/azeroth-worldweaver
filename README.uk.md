## Спільний Azeroth

Azeroth Worldweaver з’єднує **Claude** і **Codex** із приватним сервером World of Warcraft 3.3.5a на AzerothCore та mod-playerbots. Обидва компаньйони можуть спиратися на спільний контекст зі стану сервера, пам’ятати нещодавні сесії та перетворювати звичайні повідомлення дозволеного гравця на обмежені дії персонажа, які перевіряє сервер.

Репозиторій містить вихідний код і матеріали для інтеграції. Тут немає самого AzerothCore, клієнта гри, ігрових даних, дампів бази, конфігів сервера, журналів чи паролів.

## Що вміють компаньйони

| Можливість | Як працює |
|---|---|
| Спільний контекст світу | Учасники групи, завантажені істоти й об’єкти поблизу, ціль, інвентар та екіпірування, навички й спели, стан завдань, події та час оновлення даних. Незавантажені й невидимі частини світу залишаються невідомими. |
| Вільна розмова та пам’ять сесій | Адаптери враховують недавню розмову й локальні підсумки попередніх сесій. Пам’ять приватна, не потрапляє в Git і не дає дозволу на дії. |
| Полювання | Можна полювати на один або кілька типів ворожих істот у поточній місцевості чи вибраній карті/зоні/районі. Боти рахують вбивства, обмежують бій заданими цілями, збирають звичайний лут із цих трупів і повідомляють про перебіг. |
| Збір і передача луту | Зібрані речі залишаються в сумках бота. Передача — окремий наказ: міст кладе лише запитані речі, придатні для обміну, у звичайне вікно WoW; гравець підтверджує обмін. Кількість стеків перевіряється за актуальним інвентарем. |
| Дії персонажа | Іти за гравцем або чекати, атакувати його ціль чи доступного ворога, застосувати відомий спел, використати або вдягнути річ, рибалити, взаємодіяти з NPC та вибирати пункт із меню, яке повернув сервер. Діють звичайні перевірки гри. |
| Провідник | Пройти до корисного місця появи істоти на тій самій ігровій карті й чекати, поки гравець наздожене. Без телепортації та переходу на інші карти. |
| Довідка про світ | Обмежені запити лише для читання про істот, завдання, риболовлю, лут, предмети, спели й точки появи. Дані бази позначаються окремо від того, що сервер бачить зараз. |
| Знімок гри за запитом | Перевірений кадр активного вікна WoW можна отримати лише на прохання. Фонове й повноекранне захоплення вимкнене. |

### Приклади наказів у грі

- «Codex, полюй на всіх тролів у цій місцевості, збирай лут і повернися».
- «Claude, підійди до найближчого місця з Tangy Clam Meat і покажи мені дорогу».
- «Передай мені весь Thick-shelled Clam».
- «Codex, застосуй Healing Wave до Claude».

Агент зіставляє прохання зі свіжим контекстом і доступними діями; якщо не вистачає деталей, може перепитати. Сам факт наказу не означає, що дія вдалася: міст повертає результат, а агент звіряє його зі станом сервера. Доступність пунктів NPC визначає сервер у поточний момент. Автоматизація не означає, що вже підтриманий кожен квест, тренер чи особливий сценарій NPC.

## Як це працює

1. Модуль AzerothCore записує спільний обмежений знімок світу й журнал подій.
2. Адаптери Claude і Codex читають той самий контекст, локальну пам’ять і повідомлення дозволеного персонажа.
3. Адаптер формує типізований запит; модуль перевіряє виконавця, власника, групу, ціль, стан і параметри.
4. AzerothCore/mod-playerbots виконує підтриману дію. Результат і спостережені події повертаються агентам.

Телеметрія — це не відео з гри. Вона описує лише завантажені сервером об’єкти в межах заданої видимості та лімітів. Знімок клієнта — окреме спостереження за запитом. Дальність, видимість, відновлення здібностей, інвентар, можливість обміну й остаточний результат визначає сервер.

## Структура репозиторію

```text
modules/mod-claude-bridge/   модуль AzerothCore: телеметрія, події та диспетчер дій
 tools/wow-agent/            адаптери Claude/Codex, пам’ять, запити, дії та знімки вікна
patches/azerothcore/         невеликий патч сумісності ядра
patches/mod-playerbots/      фільтрація цілей полювання
assets/                      оригінальні SVG-ілюстрації
 docs/design/                архітектура та специфікація дій
 tests/                      модульні тести адаптерів і телеметрії
```

## Що потрібно

- AzerothCore для WotLK 3.3.5a та гілка mod-playerbots `Playerbot`. Приватну інтеграцію розроблено для AzerothCore `3f2969ddb0da42b48b4fca050c02b19163ba1e20` і mod-playerbots `e88cc4099e69f35126b28942a412ca702d20453b`; на інших ревізіях може знадобитися адаптація.
- Інструменти C++ і CMake, потрібні вашій збірці AzerothCore. Після додавання `.cpp` повторно запустіть конфігурацію CMake.
- Python 3.10+, клієнт MySQL, Codex CLI та Claude Code CLI для відповідних адаптерів.
- Локально ввімкнений SOAP для ігрових дій. Залиште його на localhost або довіреній приватній мережі.
- Для знімків вікна — за потреби інструменти X11 та Pillow.

## Загальний порядок інтеграції

Це пакет для тих, хто вже адмініструє AzerothCore, а не інсталятор в один клік. Перед змінами зробіть резервну копію власного коду й бази. Не копіюйте приватні файли сервера в цей репозиторій.

1. Додайте `modules/mod-claude-bridge/` до каталогу `modules/` вашого дерева AzerothCore.
2. Застосуйте `patches/azerothcore/combined-phase-mask-accessor.patch` до ядра, а `patches/mod-playerbots/task-hunt-targets.patch` — до відповідного mod-playerbots. Другий патч додає обмеження цілей полювання.
3. Повторно сконфігуруйте CMake, зберіть та встановіть worldserver звичним для вашого AzerothCore способом. Перенесіть налаштування з `conf/claude_bridge.conf.dist` у локальний конфіг модуля й задайте обидва імені ботів та шляхи до телеметрії й журналів.
4. Встановіть `tools/wow-agent/` і два shell-помічники поруч із локальним runtime сервера. Через змінні середовища задайте SOAP URL і шлях до файлу облікових даних із правами `0600` (`користувач:пароль`). У прикладах немає паролів.
5. Запустіть по одному адаптеру для кожного бота з однаковим явним `WOW_AGENT_AUTHORIZED_PLAYERS` та спільним приватним каталогом телеметрії. Перевірте параметри ізоляції до запуску.
6. Спочатку перевірте роботу з приватним тестовим персонажем і перегляньте журнал дій, логи сервера та результат у грі.

Деталі є в [`tools/wow-agent/README.md`](tools/wow-agent/README.md), [`config.example.env`](config.example.env), `conf/claude_bridge.conf.dist` та [`SECURITY.md`](SECURITY.md).

## Стан проєкту

Перелічені вище можливості реалізовані у вихідному коді цього експорту. У приватному середовищі перевіряли живі знімки світу, типізовані дії, полювання з локальним і віддаленим пошуком цілей, збір луту з трупів, формування пропозиції обміну за інвентарем і підтвердження обміну гравцем. **Чисту збірку та встановлення з публічного репозиторію ще не перевірено.** API ядра й mod-playerbots залежать від ревізії; використовуйте вказані ревізії та патчі й перевіряйте інтеграцію на приватному тестовому сервері.

Модульні тести Python запускаються так:

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
python3 -m unittest discover -s tools/wow-agent/tests -p 'test_*.py'
```

## Безпека й приватність

- Список дозволених персонажів порожній за замовчуванням. Завдання може почати лише точно вказане ім’я.
- Дії типізовані й обмежені модулем та перевірками AzerothCore; це не загальна оболонка команд чи SQL.
- Не відкривайте адаптери, SOAP, логи й телеметрію недовіреним користувачам. Захистіть локальний обліковий запис і файл пароля.
- Пам’ять, історія чату, курсори, знімки, конфіги й файли бази — приватні runtime-дані; не додавайте їх у Git.
- Перед інтеграцією з сервером, де є інші гравці чи важливі дані, прочитайте [`SECURITY.md`](SECURITY.md).
